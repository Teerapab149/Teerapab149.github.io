## 1. `#roles` — เส้นวาดมือพาดทะลุคำว่า "the" (งานหลักของพรุ่งนี้)

**อาการ** เส้นมิ้นต์รอบคำ "the system" ไม่ได้ล้อมคำ แต่**ตัดผ่านกลางตัวอักษร** อ่านเป็นขีดฆ่า
· ยืนยันด้วย screenshot แล้วทั้งที่ 1440 และ 390 — **เหมือนกันทั้งสองความกว้าง**

**นี่ไม่ใช่บั๊กน้ำหนักเส้น** น้ำหนักแก้ไปแล้วเมื่อ 2026-08-03 (ดู §3) และวัดได้ตรงทุกจุด
· ตัวปัญหาคือ**เรขาคณิต** ของกฎกลาง `verdure.css`:

```css
.mark-wrap > .scrawl { inset: -18% -7% -18% -7%; width: 114%; height: 136%; z-index: 2; }
```

**ห้ามแก้กฎกลางตัวนี้** เพราะ hero ("actually use") กับ `#contact` ("problem") ใช้ร่วมกัน
และสองจุดนั้นตอนนี้ดูดี — ขยับค่ากลางเมื่อไรสองจุดนั้นเปลี่ยนตามทันที

**วิธีที่ควรใช้: เขียนกฎ scoped ให้ `#roles` อย่างเดียว** — มีตัวอย่างที่ทำสำเร็จมาแล้วในไฟล์เดียวกัน
`.cover__name` เจอปัญหาเดียวกันเป๊ะ (เส้นอ่านเป็นขีดฆ่าบนนามสกุลที่เป็นตัวกลวง) และแก้ด้วย

```css
.cover__name .mark-wrap > .scrawl { inset: auto -5% -16% -4%; width: 109%; height: 46%; }
```

คือ **เปลี่ยนจาก "วงรอบคำ" เป็น "ขีดใต้บรรทัด"** · ลอกแนวคิดนี้ไปใช้กับ `#roles` แล้วปรับตัวเลขเอง
· ค่าที่ cover ใช้จะไม่พอดีกับ `#roles` เพราะคนละขนาดตัวอักษร (`.big--xl` 152px vs `.big--l` 102.4px)
**ต้องวัดใหม่ ห้ามลอกตัวเลข**

**เกตของงานนี้**
- screenshot `#roles` ที่ 1440 · 1024 · 390 แล้วอ่านคำว่า "the system" ออกครบทุกตัวอักษร
- hero กับ `#contact` **ต้องไม่เปลี่ยนเลย** — screenshot เทียบก่อน/หลัง
- เส้นต้องไม่โดน clip หาย · มีคอมเมนต์ที่ `verdure.css` ~บรรทัด 697 เตือนว่า clip-path ทุกอัน
  ต้องใช้ inset ติดลบ ไม่งั้นจะตัดเส้นที่ห้อยใต้คำทิ้ง

## 2. แถบเมนูหายบนหน้า contact — บริบทเต็ม เผื่อยังไม่จบ

**สาเหตุที่ยืนยันแล้วจากเบราว์เซอร์จริง** `verdure.js` ~บรรทัด 61

```js
const darkSections = Array.from(document.querySelectorAll('.cover, .act-dark, .end'));
```

`overDark()` คืน true ถ้าตัวใดคร่อมเส้น 59px → ใส่คลาส `bar--dark` → `verdure.css` ~บรรทัด 188
ตั้ง `background: transparent; color: var(--paper)`

**แต่ `.end` พื้นสว่าง** วัดได้ `rgb(223, 227, 218)` ซึ่งคือ `--paper` เป๊ะ
→ **ตัวหนังสือสี `--paper` บนพื้นสี `--paper` = contrast 1.00:1** มองไม่เห็นทั้งจอสุดท้าย
ซึ่งเป็นจอที่มีปุ่มติดต่อ = จอที่สำคัญที่สุดของพอร์ต

คอมเมนต์ที่ `verdure.js` ~บรรทัด 173 พูดถึง *"a dark ending"* แปลว่า **`.end` เคยเข้มจริงตอนเขียน**
แล้วองก์มืดถูกย้ายมาอยู่*ก่อน* contact ส่วน `.end` กลายเป็นสว่าง แต่ไม่มีใครเอาชื่อออกจากรายชื่อ

**ข้อคิดที่ควรเก็บ ไม่ใช่แค่แก้บั๊ก** ต้นเหตุคือ**รายชื่อคลาสที่ไม่ตามความจริง**
ถ้าลบ `.end` ทิ้งเฉย ๆ คราวหน้ามี section ใหม่ก็พังแบบเดิม
· แต่**อย่า over-engineer** — คอมเมนต์ที่บรรทัด ~58-60 บอกว่าเลือกวิธีนี้เพราะถูกกว่าการถามเอกสาร
ว่าอะไรอยู่ใต้แถบ ซึ่งโค้ดนี้รันทุกเฟรมใน rAF · ถ้าทางใหม่แพงกว่าเดิมต่อเฟรม
**ให้เลือกทางลบชื่อออกแล้วเขียนคอมเมนต์เตือนไว้แทน**

## 5. หนี้ที่ยังไม่มีใครถือ นอกจากข้างบน

- **`setTimeout 4000ms`** ใน `<head>` ของ `index.html` ไม่มีคอมเมนต์บอกที่มา
  · ข้อเสนอ: **อย่าแตะเลข เขียนอสมการลงไปแทน** — เพดาน **5000ms คือของแข็ง**
  (`curtain-failsafe` เป็น CSS ล้วนที่ซ่อนม่านที่ 5s ถ้า failsafe ยิงหลังจากนั้นจะมีช่วงที่ม่านหาย
  แต่ cover ยังว่าง) · พื้น **3720ms คือของอ่อน** (`--lead` 3600 + 120 = จังหวะที่ entrance เริ่มในโหลดปกติ)
  · 4000 เกาะขอบล่างซึ่งเป็นฝั่งที่ถูก · เขียน `3720 < X < 5000` ไว้ให้คนที่มาแก้ `--lead` ทีหลังรู้ว่า
  ต้องคิดสามค่าพร้อมกัน · **นี่ไม่ใช่การแต่งเหตุผล** เพราะไม่ได้อ้างว่ารู้ว่าทำไมถึงเป็น 4000
  แค่บอกว่ามันต้องผ่านเงื่อนไขอะไร ซึ่งวัดได้
- **contrast กับ responsive ยังไม่ได้วัดซ้ำทั้งชุดหลังรอบ 2026-08-02** — ตัวเลข "ผ่านทั้ง 20 ชุด"
  ใน HANDOFF §1 เป็นของ 2026-07-30 ซึ่งตอนนั้นยังไม่มีราง ไม่มีองก์มืด ไม่มีม่านโหลด
  · **และตอนนี้ยังไม่มีเส้นชั้นความสูงด้วย** ซึ่งเพิ่งใส่วันนี้ · จุดที่ควรวัดก่อนคือ `.rail__pin`
  ที่ `overflow: hidden` และช่วง 860–1000px
- **`curtain.js` · `inner.js` · `morph.js` ยังไม่ถูก track ใน git** (§6 ข้อ 1) — **ตัวบล็อกการ push**
  ถ้า commit แล้ว push ตอนนี้ เว็บจริงจะ 404 สามไฟล์นั้นทันที

## 6. เกตที่ต้องผ่านทุกครั้งที่แตะหน้าแรก

1. `scrollWidth === clientWidth` ที่ **1440 / 1024 / 768 / 390 / 360**
2. contrast ≥4.5:1 (ตัวเล็ก) และ ≥3:1 (ตัวใหญ่) · **สีที่มี alpha ต้องผสมทับพื้นก่อนวัด**
   · `color-mix()` คืนค่าช่อง 0–1 ส่วน `rgb()` เป็น 0–255 — แยกไม่ออกจะได้ผลว่าตกเกณฑ์ทั้งหน้า
3. `window.__i18nCheck()` ต้องว่าง · **แต่ผ่านไม่ได้แปลว่าแปลครบ** (HANDOFF §17 กล่องแดง)
   ต้องสลับไทยแล้วไล่อ่านด้วยตา รวมทั้งสี่แผงในราง
4. ทดสอบ **"ไม่มี JS" พร้อมกับ "reduced motion"** ไม่ใช่แยกกัน (HANDOFF §18.6 บทเรียนที่ 2)
5. console ไม่มี error
6. 🔴 **รัน preview ตอนพาเนลแสดงผลอยู่จริง** — ถ้า `document.visibilityState` เป็น `hidden`
   เบราว์เซอร์จะไม่ยิง `requestAnimationFrame` เลยและ `scrollTop` ค้างที่ 0
   ทำให้ทุกอย่างที่ขับด้วย scroll ดูเหมือนตายทั้งที่ปกติดี
