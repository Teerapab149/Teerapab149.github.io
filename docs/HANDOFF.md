## 4. Deploy ฟรี — GitHub Pages (แนะนำ)

workflow เขียนรอไว้แล้วที่ `.github/workflows/deploy.yml` — push ขึ้น branch `main` แล้วมันจะ
publish ให้เอง ไม่ต้อง build อะไร

repo อยู่ที่ **https://github.com/Teerapab149/Teerapab149.github.io** และ
**Pages เปิดใช้งานแล้ว** — ตรวจสดเมื่อ 2026-07-30 ว่า https://teerapab149.github.io/
เสิร์ฟหน้าเวอร์ชันอังกฤษ + About me จริง (ทั้ง 4 หน้าตอบ 200) ดังนั้น
**push เข้า `main` = เผยแพร่ทันที** รอ 1-2 นาทีให้ workflow รันจบ

ถ้าวันหนึ่งเว็บไม่อัปเดตหลัง push ให้ดูแท็บ Actions ว่า job `deploy` เขียวไหม
· ถ้าไม่มี workflow รันเลย ให้เช็ค **Settings → Pages → Build and deployment → Source = GitHub Actions**

ถ้า push ใหม่แล้วเว็บไม่อัปเดต ให้ดูแท็บ Actions ว่า job `deploy` เขียวไหม
· ถ้าไม่มี workflow รันเลย แปลว่ายังไม่ได้ตั้ง Source เป็น GitHub Actions

**ทางเลือกฟรีอื่น ๆ** (ถ้าไม่อยากใช้ GitHub Pages)
- **Cloudflare Pages** — ต่อ repo แล้วตั้ง build command ว่าง, output directory = `/` · ฟรี ไม่จำกัด bandwidth
- **Netlify** — ลาก folder ทั้งอันไปวางบนหน้า drop ได้เลย ไม่ต้องมี git
- **Vercel** — import repo, framework preset = Other

ทุกเจ้าเสิร์ฟไฟล์ static ตรง ๆ ไม่ต้อง build ดังนั้นย้ายไปมาได้อิสระ

**ทุก path ในหน้าเว็บเป็น relative (`assets/...`) ทั้งหมด** — ย้ายไป subpath ไหนก็ไม่พัง
อย่าเปลี่ยนเป็น absolute path (`/assets/...`) เด็ดขาด ไม่งั้น GitHub Pages แบบ subpath จะรูปหายทั้งหน้า

### กับดักที่เจอจริงตอนทำ (อย่าทำซ้ำ)

- **`.portrait` ต้องมี `width: 100%` คู่กับ `max-width` + `margin-inline: auto`** ที่ ≤900px
  ไม่งั้นรูปหดเหลือ 192px เพราะ **auto margin ปิด stretch ของ grid item** แล้วกล่องหดตาม fit-content
- **parallax ต้องใส่ที่ `.portrait__frame` ไม่ใช่ที่ `<figure>`** เพราะ figure เป็นเป้าของ `.up`
  และ `.js-anim .up.is-in { transform: none }` specificity สูงกว่า → transform ที่ตัว figure ถูกกินเงียบ ๆ
- **ตัวโครงร่างต้องอยู่ใน `@supports (-webkit-text-stroke: …)`** ไม่งั้นเบราว์เซอร์ที่ไม่รู้จัก
  จะเหลือแค่ `color: transparent` = นามสกุลหายไปทั้งคำ (ผิดกติกาข้อ 3 ของ `CLAUDE.md` เต็ม ๆ)
- **`--honey-ink` ใช้ได้แต่บนพื้นครีม** บนแผงมอสมันเหลือ 1.7:1 — บนมอสต้องใช้ `--honey` (4.7:1)
- **เส้น scrawl บนคำต้องย้ายลงมาเป็นเส้นใต้เมื่อคำเป็นตัวโครงร่าง** ค่า inset ปกติวาดพาดกลางคำ
  ซึ่งบนตัวโครงร่างขนาดใหญ่อ่านเป็น "ขีดฆ่าชื่อ" (ดู `.cover__name .mark-wrap > .scrawl`)
- **`.stage` ต้องมี `background` กับ `z-index: 1`** ไม่งั้น cover ที่ pin อยู่จะทะลุขึ้นมาให้เห็น
  แทนที่จะถูกทับ · และ **`.cover` ต้องประกาศ background ของตัวเองไว้หลัง `.stage`**
  เพราะ specificity เท่ากัน ใครอยู่ท้ายไฟล์ชนะ — ตอนแรกลืมข้อนี้แล้วแผงกลายเป็นครีม
  ตัวหนังสือครีมบนครีม = จอแรกว่างเปล่าทั้งจอ
- **การ pin ต้องวัดว่า cover สูงพอดีจอไหม ห้ามเดาด้วย media query** — panel ที่สูงเกินจอแล้ว pin
  จะซ่อนส่วนที่เกินไว้ตลอดกาล · โน้ตบุ๊ก 1366×768 กับ 1280×720 คือจุดที่เดาแล้วพลาด
  (แถวข้อมูลแถวสุดท้ายหายไปเลย) · ตอนนี้ `verdure.js` วัด `cover.scrollHeight <= innerHeight`
  แล้วค่อยใส่ `html.is-pinned` และวัดใหม่ทุกครั้งที่ resize
  · และมี `@media (max-height: 940px)` รีดอากาศของ cover ลง (padding, gap, ขนาดชื่อผูกกับ `svh`)
  เพื่อให้จอเตี้ยยัง**ผ่าน**เกณฑ์ ไม่ใช่ปล่อยให้ฟีเจอร์เงียบไป
- **`--cp` ต้องวัดจากขอบบนของ hero ไม่ใช่จาก cover** เพราะ cover เป็น sticky
  พอ pin แล้ว rect ของมันหยุดขยับ ค่าที่คำนวณจะค้างที่ 0 ตลอด
- **`html.is-ready` รอ `document.fonts.ready` (cap 700ms)** ถ้าเริ่ม wipe ตอน Kanit ยังสลับฟอนต์
  ตัวอักษรจะกระตุกกลางแอนิเมชัน · cap ไว้เพื่อไม่ให้ CDN ช้าทำให้ cover ค้างที่ start state
- **`clip-path` end state ต้องใช้ inset ค่าติดลบ** (`inset(-32% -7%)`) ถ้าใช้ `inset(0)`
  มันจะตัดพอดีขอบกล่อง = เส้น scrawl ที่ห้อยใต้นามสกุลหายไป
- **pill `00 — scroll` ทับแถวข้อมูลบนจอ 768px** เลยซ่อนตอนอยู่บน cover ด้วย `.bar--dark ~ .count`
  (ใช้ class ที่มีอยู่แล้ว ไม่ต้องเพิ่ม JS) · บน cover มี cue ของตัวเองอยู่แล้วจึงไม่เสียอะไร

**กรอบรูปเป็นทรง arch ไม่ใช่ทรงแคปซูล** — ตั้งใจให้ไม่เหมือน `.capsule` / `.grow__card`
เพราะสองอันนั้นต้องอ่านว่าเป็น "วัตถุเดียวกันที่กำลังเปิดออก" ตอน scroll
ถ้าเอารูปตัวเองไปใช้ทรงเดียวกัน คนจะอ่านเป็นวัตถุที่สามและ effect นั้นพัง

**ช่องว่างก่อนคำที่มีเส้นวงกลม (`.mark-wrap`) ต้องอยู่นอก `<span>`** — ตอนแปลเป็นอังกฤษเคยเขียน
`people<span class="mark-wrap"> actually use…` แล้วช่องว่างหน้าคำถูกกลืนหาย เพราะ leading space
ที่ต้นของ inline-block ถูก collapse → อ่านเป็น "peopleactually" · ภาษาไทยไม่เจอปัญหานี้เพราะไม่มีเว้นวรรค

**ตรวจ responsive ด้วย iframe ได้เร็วกว่า resize จริง** — สร้าง iframe กว้างตามที่ต้องการทดสอบ
โหลดหน้าเข้าไป แล้วไล่ `getBoundingClientRect()` ทุก element ข้ามตัวที่อยู่ใต้กล่อง `overflow-x`
(ดูเหตุผลที่ห้ามใช้ `scrollWidth` ใน §10) · 4 หน้า × 5 ความกว้าง จบใน JS call เดียว
· **ข้อควรระวัง: iframe ที่วางไว้ `left:-9999px` จะไม่โหลดรูป `loading="lazy"`** ถ้าจะวัดรูปต้องวัดในแท็บจริง

### `assets/reveal.js` — engine กลางของทั้ง 5 หน้า

โหลด**ก่อน** verdure.js / app.js / motion.js ทุกหน้า (i18n.js อ่าน `window.__lmRestore` ตอนโหลด)
ถือสองอย่าง: line-mask engine กับ IntersectionObserver ที่แจก `.is-in`
· **ห้ามสร้าง observer ตัวที่สองในไฟล์อื่น** element ที่ถูก observe สองที่จะแย่งคลาสกัน

ข้อควรระวังของ line-mask ที่แลกมาด้วยบั๊กจริง:
- อ่านทั้งหมดก่อนเขียนทีเดียว (Range ละคำ) → เสีย layout รอบเดียว **วัดได้ 0.15ms/element**
- re-split เฉพาะตอน**ความกว้าง**ของ element เปลี่ยน — ถ้าไปฟังความสูงจะ loop ไม่จบ
  เพราะการ split เปลี่ยนความสูงเอง · debounce 180ms · ทดสอบแล้ว resize รัว 6 ครั้ง = rebuild 2 ครั้ง
- ถ้า child element กินเกิน 1.65 เท่า line-height (คือมันตกบรรทัด) **จะไม่ split** เลย
  เพราะจะฉีก `<em>`/`<svg>` ออกจากกัน → ตกไปใช้ `.up` · เกิดจริงที่ h1 ของ credit-tracker
  ตอนจอ ≤1024 ซึ่งถูกต้องแล้ว ไม่ต้องแก้
- **ห้าม split ภาษาไทยต่ำกว่าระดับบรรทัด** สระ/วรรณยุกต์เป็น combining mark จะ render พัง

### 17.1 ของที่ `i18n.js` แตะไม่ได้เลยโดยโครงสร้าง — ไม่ใช่ selector ที่ลืม

> เขียน 2026-08-03 หลังรันเกต §18.7 ข้อ 6 · **ห้ามพยายาม "แก้" ด้วยการเพิ่ม selector**
> ทั้งสามกลุ่มนี้เพิ่มไปก็ไม่ได้ผล และสองกลุ่มแรกจะพังกว่าเดิม

engine ของ `i18n.js` ทำได้อย่างเดียวคือ **เขียน `innerHTML` ทับ element แรกที่ selector match**
ข้อจำกัดนั้นทำให้มีของสามตระกูลที่อยู่นอกมือมันถาวร

| ตระกูล | ของจริงในหน้า | ทำไมเพิ่ม selector ไม่ช่วย |
|---|---|---|
| **JS เขียนทับทุกเฟรม** | `#count` มุมจอ (`00 — scroll`) · `.grow__meas` (`372 px · phone`) | `verdure.js:181` กับ `:151` เขียนค่าใหม่ทุกเฟรมที่ scroll · คำแปลจะถูกลบทิ้งทันทีที่ขยับจอ — **ตระกูลเดียวกับกับดัก `.rail__count` แต่คนละกลไก** · แก้ได้ที่ `verdure.js` ที่เดียว |
| **ข้อความที่มาจาก attribute** | `.swap[data-label]` = `Say hello` / `Call me` ตอน hover ปุ่มติดต่อ | `verdure.css:2023` ใช้ `content: attr(data-label)` · engine **แตะ attribute ไม่ได้เลย** แตะได้แค่ `innerHTML` · `style.css:1066` มีกฎเดียวกัน แต่หน้า case study เป็นอังกฤษล้วนอยู่แล้วจึงไม่กระทบ |
| **ข้อความที่ไม่ได้เห็นด้วยตา** | `alt` ของรูปทุกใบ · `aria-label="Language"` | เหตุผลเดียวกับแถวบน — เป็น attribute · **และการไล่อ่านด้วยตาก็จับไม่ได้ด้วย** คนที่เจอคือคนใช้ screen reader ภาษาไทย |

🔴 **แถว 2 กับ 3 คือจุดบอดของเกต §18.7 ข้อ 6 เอง** — การไล่อ่านด้วยตาจับตระกูลแรกได้
แต่จับ attribute ไม่ได้ เพราะ `data-label` โผล่เฉพาะตอน hover และ `alt` ไม่โผล่เลย
· **เวลาจะปิดช่องนี้จริง ต้องขยาย engine ให้เขียน attribute ได้ ไม่ใช่เพิ่มบรรทัดในทะเบียน**
· ทั้งหมดนี้**ยังไม่แก้ และเป็นเรื่องที่เจ้าของควรตัดสิน** ว่าคุ้มกับการแตะ engine ไหม

ตอนนี้ม่านโหลดเป็นเฟรมแรก และ `.cover` คือสิ่งที่ม่านเปิดออกมาให้เห็น
· ผลข้างเคียงที่ต้องรู้: **`.cover` ไม่มีคลาส `.scene` แล้ว** จึง**ไม่ได้อยู่ในรายชื่อที่
`reveal.js` observe** — ถ้า `curtain.js` ไม่ทำงาน จะไม่มีใครใส่ `.is-in` ให้มันเลย
นี่คือเหตุผลทั้งหมดของ inline script ตัวที่สาม (ดู §18.4)

### 18.2 ตารางไฟล์ของหน้าแรก และทำไมลำดับโหลดสำคัญ

**ใน `<head>` (ตามลำดับจริง)**

| ลำดับ | อะไร | ทำไมต้องอยู่ตรงนั้น |
|---|---|---|
| 1 | `verdure.css` | design system ทั้งชุด |
| 2 | `rail.css` | **ต้องมาหลัง** `verdure.css` — มันต่อยอด ไม่ได้แทนที่ · สี type step motion token ทุกตัวมาจากไฟล์แรก |
| 3 | inline `js-anim` | gate ของ start state ทุกอันในเว็บ |
| 4 | inline `nav-in` | ครึ่งขาเข้าของ page wipe |
| 5 | inline failsafe 4000ms | ตาข่ายรองของ `.cover` |
| 6 | **`morph.js` แบบ blocking** | `pagereveal` ยิงที่ **first render** ของหน้าปลายทาง · `defer` สัญญาแค่ว่ามาก่อน `DOMContentLoaded` ซึ่ง**สายเกินไป** · พลาด event นี้ = แผงบินไปกลายเป็นกล่องเปล่า · ตัวไฟล์มีแค่ listener สองตัวกับ class เดียว ไม่มีอะไรให้ defer |

| ท้าย body 7 | `nav.js` | wipe ระหว่างหน้า | ลิงก์ธรรมดา |

**กฎลำดับที่ละเมิดไม่ได้**

1. **`reveal.js` ต้องมาก่อน `verdure.js` / `app.js` / `motion.js` และก่อน `i18n.js`**
   — `i18n.js` เรียก `window.__lmRestore()` ซึ่ง `reveal.js` เป็นคนนิยาม
   ถ้าสลับลำดับ การสลับภาษาจะเขียนทับ heading ที่ split แล้ว = พังทั้งสอง
2. **`morph.js` ต้อง blocking ใน `<head>` ทั้ง 5 หน้า** ไม่ใช่แค่หน้าแรก
   เพราะครึ่ง `pagereveal` เกิดที่**หน้าปลายทาง**
3. **`curtain.js` ต้องเป็น script แรกใน `<body>`** — overlay ต้องมีอยู่ก่อน paint แรก
   ไม่งั้นหน้าจะแวบให้เห็นหนึ่งครั้งก่อนถูกปิด แล้วอ่านเป็น glitch ไม่ใช่ entrance
   · ที่แยกเป็นไฟล์ (แทนที่จะ inline) **เพื่อให้อ่านและรีวิวได้เท่านั้น** ไม่ใช่เพื่อ cache
4. **`rail.css` ต้องมาหลัง `verdure.css`**

### 18.3 กับดักที่ฝังอยู่ในโค้ดจริง — ส่วนที่มีค่าที่สุดของหัวข้อนี้

ทุกข้อข้างล่างมาจากคอมเมนต์ในไฟล์ ซึ่งเขียนโดยคนที่เจอปัญหานั้นมาแล้ว

**`curtain.js` — ม่านโหลด**

- **`querySelector('.cover')` ต้องเรียกตอน `reveal()` ไม่ใช่ตอนหัวไฟล์** — สคริปต์นี้รันเป็นตัวแรก
  ใน `<body>` ตอน parse ยังไปไม่ถึง `<section>` เลย · เคย cache ไว้ข้างบนแล้ว **cover ไม่เคย
  ถูกเปิดเลยเงียบ ๆ**
- **การปล่อยม่านขับด้วย `setTimeout` ไม่ใช่ frame loop** — เบราว์เซอร์หยุดจ่าย animation frame
  ให้แท็บที่อยู่เบื้องหลัง ถ้าพึ่งตัวนับอย่างเดียว คนที่สลับแท็บไปจะกลับมาเจอจอทึบค้าง
- **ม่านไม่ทำงานเมื่อมาจากหน้า case study** — `nav.js` เขียน `sessionStorage['nav']` ไว้
  และม่านเช็กค่านั้น · ม่านเต็มจอสองชั้นซ้อนกันอ่านเป็นการสะดุด
- **ตัวนับ *scrub* ไม่ใช่ *step*** — `MIN 1200ms` เป็นพื้นเทียมที่ซื้อความตึง (cache อุ่นโหลดเสร็จ
  ใน ~50ms ตัวเลขจะกระโดด 0→100 ในสองเฟรม) · เพดาน 92% ระหว่างที่ของจริงยังมาไม่ถึง
  **เพื่อให้ตัวเลขรอของจริงจริง ๆ ไม่ใช่โกหก** · `MAX 2600ms` คือเพดานเวลา
- **สิ่งที่ตัวนับรอคือ `document.fonts.ready` กับ `img.decode()` ของ `portrait.webp`** เท่านั้น
- **failsafe สามชั้นซ้อนกัน** เพราะมันบังทั้งหน้า:
  `--lead` default `3600ms` ใน CSS (entrance ของ cover เล่นเองแม้ JS ตาย)
  · inline script 4000ms ใน `<head>` (ใส่ `.is-in` ให้ cover)
  · `@keyframes curtain-failsafe` ซ่อน `.loader` ที่ 5s
- `.cover__stack` ใช้ **`translate` ไม่ใช่ `transform`** เพราะ `transform` ถูกจองไว้ให้ exit
  ที่ขับด้วย `--cp` แล้ว · property แยกกันจึงประกอบกันได้โดยไม่ต้องรู้จักกัน

**`rail.js` / `rail.css` — ราง Work**

- **สถานะฐานคือ filmstrip ที่ปัดได้ ไม่ใช่ pin** — เขียนกลับหัวจากรางแบบทั่วไปโดยตั้งใจ
  `.rail__track` เป็น `overflow-x: auto` + `scroll-snap` ธรรมดา ใช้ได้ทั้งไม่มี JS บนมือถือ
  และใต้ reduced motion · pin ถูก**ทับลงไปทีหลัง**เมื่อ `rail.js` ใส่ `html.can-pin`
  **โหมดล้มเหลวจึงเป็น "แถบที่ปัดเอา" ไม่ใช่ "สามโปรเจกต์ที่เข้าไม่ถึง"**
- **`rail.js` ปฏิเสธการ pin สามกรณี**: reduced motion · จอแคบกว่า **1000px** (การยึด scroll
  แนวตั้งไปเลื่อนของแนวนอนบนมือถือคือการสู้กับท่าที่อุปกรณ์ทำได้ดีที่สุด) · track ไม่ได้กว้าง
  เกินจอจริง (`overflow <= 40`)
- **ความสูงของรางคำนวณจากระยะที่ track ต้องเดิน ไม่ใช่ `400vh` ตายตัว** — 1px ของ scroll
  = 1px ของการเลื่อนข้าง · เลขตายตัวคือเหตุผลที่รางแบบนี้รู้สึกอืดหรือกระตุกต่างกันไปตามจอ
- **ต้องเซ็ต `--rx: 0px` ก่อนวัด `scrollWidth`** ไม่งั้นค่าที่วัดได้รวมระยะที่ลากไปแล้ว
- **resize ต้อง `measure()` ก่อน `draw()`** — ทั้งความกว้าง track และความสูงรางเปลี่ยนตามจอ
  วาดด้วยตัวเลขเก่าคือวางแผงผิดที่ · debounce 150ms
- **`document.fonts.ready` ต้อง measure ใหม่** เพราะฟอนต์เปลี่ยนความสูงข้อความในแผง
  ซึ่งเปลี่ยนความกว้างของ track ได้
- **`.rail__pin` ต้องมี `padding-top: calc(var(--bar) + 10px)`** ไม่งั้นหัวรางไปอยู่ใต้แถบบน
  แล้วตัวนับ `01 / 04` — สิ่งเดียวที่บอกว่าอยู่ตรงไหนของราง — หายไปทั้ง section
- **`overflow: hidden` บน `.rail__pin` คือสิ่งที่กัน body ไม่ให้ scroll แนวนอน** ห้ามถอด
- **`.unveil` เปิดจากล่างขึ้นบน สวนทางกับ `.wipe` ที่เปิดจากบนลงล่าง — เป็นการตัดสินใจ ไม่ใช่ความพลาด**
  `.wipe` อยู่ในหน้า case study ที่ภาพมาถึงใต้หัวข้อที่อ่านไปแล้ว · ในรางแผงเองคือหัวข้อ
  ขอบที่วิ่งขึ้นไปหาตัวหนังสือด้านบนจึงพาสายตาไปทางที่รางอยากให้ไป
- **`--iy-span: 44px` ใน `rail.css` กับ `RANGE = 22` ใน `inner.js` เป็นเลขเดียวกัน** (ครึ่งหนึ่ง)
  **แก้อันหนึ่งต้องแก้อีกอัน** ไม่งั้นขอบกรอบจะโผล่
- **การ drift แนวตั้ง (`--iy`) กับการ lag แนวนอน (`--lag`) แยกกันด้วย `html:not(.can-pin)`
  ไม่ใช่ด้วย specificity** — ตอน pin ทำงาน scroll แนวตั้งถูกแปลงเป็นการเดินด้านข้างไปแล้ว
  ถ้ามี drift แนวตั้งทับอีก ภาพจะไถลลงพร้อมกับที่แผงเลื่อนซ้าย
- **`.panel--tall` (MeguBot) ถูกยกเว้นจาก drift** เพราะภาพเป็น `contain` ไม่ใช่ `cover`
  การเลื่อนรูป letterbox ในขอบว่างของตัวเองอ่านเป็นบั๊ก layout ไม่ใช่ความลึก
- **`[data-rail-to]` ต้องแปลง "พาไปแผง N" เป็น "เลื่อนหน้าไปจุดที่ N อยู่กลางจอ"**
  เพราะตอน pin แผงไม่ใช่ของที่ scroll ไปหาได้ตามปกติ

**`inner.js`**

- **ไม่มี rAF loop ถาวร** — scroll/resize ขอเฟรมเดียวแบบรวบ และ IntersectionObserver
  ตัดของนอกจอออกจากลิสต์ · scroll อยู่ท้ายหน้า = ไฟล์นี้ทำงาน 0 ต่อเฟรม
- **ตัดการเขียนที่ต่ำกว่า 0.1px ทิ้ง** — มองไม่เห็นแต่ยังกิน style recalc ทุกเฟรมทุกแผง
- **`.portrait__frame` ไม่ได้อยู่ในขอบเขตของไฟล์นี้** — มัน parallax ด้วย `--py` จาก `verdure.js`
  อยู่แล้ว · สอง driver เขียน element เดียวกันจะตีกัน ทางแก้คือย้าย `--py` จากกรอบไปที่ `<img>`

**`morph.js` — ภาพบินข้ามหน้า**

- **`startViewTransition()` ใช้ไม่ได้กับเรื่องนี้ และนี่คือความเข้าใจผิดที่ต้องกันไว้ก่อน**
  ฟังก์ชันนั้นเป็น same-document ล้วน — มัน snapshot หน้า รัน callback แล้ว snapshot อีกรอบ
  · การ navigate ทำลาย document ทิ้ง จึงไม่มี snapshot ที่สองให้ถ่าย
  · ของที่ทำงานจริงคือ **`@view-transition { navigation: auto }`** ใน CSS ทั้งสองไฟล์
  ซึ่งบอกเบราว์เซอร์ให้ถือ pixel ของหน้าเก่าไว้ข้ามการโหลด · JS ได้พูดแค่สองจังหวะคือ
  `pageswap` (ขาออก) กับ `pagereveal` (ขาเข้า)
- **`'onpageswap' in window` คือการเช็กที่ซื่อสัตย์** — `document.startViewTransition` มีอยู่ใน
  เบราว์เซอร์ที่ทำได้แค่ same-document ถ้าไปเช็กตัวนั้นจะอ้าง support ที่ไม่มี
- **`from = null` ต้องรีเซ็ตทุกคลิก ไม่ใช่เฉพาะคลิกในราง** — คลิกที่จำแผงไว้แล้วไม่ navigate
  (กด Escape หรือมีใคร `preventDefault`) จะทิ้งแผงนั้นค้างไว้ แล้วการ navigate ครั้งถัดไป
  **จากที่ไหนก็ตาม**จะ morph ภาพที่คนไม่ได้มอง
- **ต้องบังคับเปิด clip ทั้งสองฝั่งด้วย `.vt-open`** เพราะ snapshot ถูกถ่ายก่อน reveal ทำงาน
  · ขาออก `.panel__media.unveil` ยังอาจ resolve ไม่เสร็จ = morph เศษเสี้ยวของภาพ
  · ขาเข้า hero มี `.wipe` ที่ยังปิดอยู่ = **แผงบินไปกลายเป็นสี่เหลี่ยมว่างเปล่า**
  · **`.is-in` อย่างเดียวไม่พอ และข้อนี้ไม่ชัดในตัวเอง** — `.is-in` เปิด clip ผ่าน transition `--t4`
  ณ วินาทีที่เบราว์เซอร์ capture ค่า computed ยังเป็น `inset(0 0 100%)` อยู่
  **วัดมาแล้ว ไม่ได้เดา** · `.vt-open` เปิดโดยไม่มี transition เลย และใส่ `.is-in` ไปด้วย
  เพื่อไม่ให้ `reveal.js` มา wipe ซ้ำตอน observer ตามมาทัน
- **กฎ `.js-anim .wipe.vt-open img` ต้องอยู่ *หลัง* กฎ `.is-in` ในไฟล์** — specificity เท่ากัน
  ใครอยู่ท้ายชนะ · **ย้ายขึ้นไปข้างบนเมื่อไร มันจะหยุดทำงานเงียบ ๆ**
- **ต้องล้าง `viewTransitionName` ใน `vt.finished`** — document เก่าถูก freeze ไม่ได้ถูกทิ้ง
  ถ้ากลับมาด้วย bfcache ชื่อนั้นยังติดอยู่แล้วจะชนกับตัวถัดไป
- **`--vt-fit` ส่ง `cover`/`contain` ข้ามหน้ามา** เพราะหน้าปลายทางไม่มีทางรู้ว่าแผงต้นทาง
  เป็นภาพหน้าจอ (crop ได้) หรือการ์ดโลโก้ของ MeguBot (crop ไม่ได้)
- **ต้องตั้ง `width/height: 100%` ให้ `::view-transition-old/new`** ไม่งั้น snapshot ทั้งสอง
  ถูกยืดตามกล่องของ group ในแต่ละขณะ = กรอบแผงกว้างบีบตัวตอนเดินไปหา hero ที่สูงกว่า
  อ่านเป็นหนังยาง
- **`morph.js` แตะเฉพาะลิงก์ใน `#work-rail`** — `navigation: auto` opt-in ให้ทุก navigation
  ใน origin เดียวกัน ซึ่งจะไปแทน wipe ของ `nav.js` ทั้งเว็บเงียบ ๆ · navigation อื่นจึงโดน
  `skipTransition()` แล้วคืนให้ `nav.js`
- **บล็อก `MORPH` ใน `verdure.css` กับ `style.css` ต้องเหมือนกันเป๊ะ** — สองไฟล์นี้คือสองปลาย
  ของ animation เดียว · ต่างกันเมื่อไร = กระตุกกลางทาง · **แก้ไฟล์หนึ่งต้องแก้อีกไฟล์**

**`feel.js` — ของที่ §17 ไม่เคยพูดถึง**

- โหลดทั้ง 5 หน้า ต่อจาก `reveal.js` · สองกลไก: **เคอร์เซอร์** (จุดที่ตามเป๊ะ + วงแหวนที่ตามช้า
  `lerp .16`) และ **drift** ของ `.shot` `.capsule` `.hero__shot` `figure.figure` ที่ ±10px
- **เคอร์เซอร์เช็ก `(pointer: fine)` ไม่ใช่ touch sniff** — คำถามที่ถูกต้องคือ "อุปกรณ์นี้จิ้ม
  เป้าเล็ก ๆ ได้ไหม" ซึ่งคือสิ่งที่จุด 6px ต้องการพอดี
- **hover state ใช้ event delegation** เพราะ gallery กับ deck ของ 23 ธีมถูกสร้างโดย `app.js`
  หลังไฟล์นี้รันจบไปแล้ว
- **drift ขยับ `<figure>` ไม่ใช่ `<img>` ข้างใน** — การขยับภาพต้องบังคับให้ทุกกรอบมี aspect
  ตายตัว + `object-fit: cover` ซึ่ง `.shot` **ตั้งใจไม่ทำ** เพราะภาพหน้าจอที่ถูก crop
  ให้พอดีกรอบคือภาพหน้าจอที่แย่ลง
- **±10px เท่านั้น** — มากกว่านี้เริ่มชนกับ caption ที่ทับขอบล่างของ `.shot`
- **เขียน `translate` ปล่อย `transform` ไว้ให้ hover scale ที่มีอยู่แล้ว**
- 🔴 **magnetic ถูกถอดออกแล้วโดยคำสั่งเจ้าของ และห้ามเอากลับ** — เดิมทำให้ `.btn`
  `.deck__nav` `.lang__btn` `.cover__cue` เอนเข้าหาเมาส์ · เจ้าของบอกว่า
  *"ทุกปุ่มเลย ... ขยับตามเมาส์ตลอด"* · ความผิดคือไปใส่ให้**คลาสของ element** แทนที่จะใส่ให้
  **ของชิ้นเดียวที่ตั้งใจ** — การเน้นทุกอย่างคือการไม่เน้นอะไรเลย ปุ่มติดต่อท้ายหน้า
  ซึ่งเป็นปุ่มเดียวที่สำคัญจริง อ่านเหมือนปุ่มสลับภาษาที่มุมจอเป๊ะ
  · ถ้าจะกลับมา ให้ใส่ **element เดียว** ที่เลือกมาโดยตั้งใจ

### 18.4 inline script สามตัวใน `<head>` ของ `index.html`

ทั้งสามตัว**ต้องอยู่ใน `<head>` ไม่ใช่ไฟล์แยก** ด้วยเหตุผลเดียวกันคือ
**ต้องรันให้เสร็จก่อน paint แรก** — สคริปต์ภายนอกไม่มีอะไรรับประกันจังหวะนั้น

| # | โค้ด | คืออะไร | ทำไมต้องอยู่ใน head |
|---|---|---|---|
| 1 | `documentElement.classList.add('js-anim')` | gate ของ start state ทุกอันในเว็บ | ถ้ารันช้ากว่า paint แรก หน้าจะแวบให้เห็นเนื้อหาเต็มก่อนแล้วค่อยหายไปซ่อน · **และถ้าบรรทัดนี้ไม่รันเลย ทั้งเว็บแสดงผลปกติครบถ้วน** ซึ่งคือกติกาข้อ 3 ของ `CLAUDE.md` |
| 2 | `if(sessionStorage.getItem('nav')) add('nav-in')` | ครึ่งขาเข้าของ page wipe · แผงที่คลุมหน้าใหม่คือ `html::before` | `nav.js` อยู่ท้าย body ซึ่งคลุมหน้าไม่ทันก่อน paint แรก — หน้าจะแวบก่อนถูกปิด |
| 3 | `setTimeout(… .cover.classList.add('is-in') …, 4000)` | **ตาข่ายรองชั้นสุดท้ายของ `.cover`** | ต้องตั้งเวลาให้เร็วที่สุดเท่าที่ทำได้ |

**ตัวที่ 3 ป้องกันอะไร — และมันจำเป็นจริง**

ห่วงโซ่คือ: `.cover` **ไม่มี `.scene` แล้ว** → ไม่อยู่ใน list ที่ `reveal.js` observe
→ **มีแค่ `curtain.js` ที่เดียวที่ใส่ `.is-in` ให้มัน**
· ถ้า `curtain.js` โหลดไม่ได้ (404) หรือ throw ก่อนถึงบรรทัด `reveal()`
`js-anim` ยังอยู่ (เพราะ inline ตัวที่ 1 รันไปแล้ว) แปลว่า start state ยังบังคับใช้
= **ชื่อ · รูป · lede · ตาราง `.bio` หายไปทั้งจอแรกอย่างถาวร** ซึ่งละเมิดกติกาข้อ 3 เต็ม ๆ
· 4000ms คือการยอมรับว่า "ช้าแต่มา" ดีกว่า "ไม่มาเลย" — ตรงกับ `--lead` default 3600ms ใน CSS
(entrance ของ `.cover__stack` เริ่มที่ `--lead + 120ms` = 3720ms) และ `.loader` ถูก
CSS keyframe ซ่อนที่ 5s ทั้งสามค่าจึงเรียงกันพอดีโดยตั้งใจ
· **ในการโหลดปกติมันคือ no-op** เพราะ `curtain.js` ใส่ `.is-in` ไปนานแล้ว และ `classList.add`
ที่ซ้ำไม่ทำอะไร

> ⚠️ **และตอนนี้มันไม่ใช่ความเป็นไปได้เชิงทฤษฎี** — `assets/curtain.js` **ยังไม่ถูก track ใน git**
> (§6 ข้อ 1) ถ้ามีใคร commit แล้ว push ตอนนี้ เว็บจริงจะ 404 ไฟล์นั้นทันที
> และ inline script ตัวที่ 3 คือสิ่งเดียวที่กันไม่ให้จอแรกว่างเปล่า

**ยังสรุปไม่ได้ ต้องให้คนยืนยัน** — ตัวเลข 4000ms เองไม่มีที่มาบันทึกไว้ที่ไหน
มันสอดคล้องกับ `--lead` 3600ms และ failsafe 5s อย่างมีเหตุผล แต่**ไม่มีคอมเมนต์บอกว่า
เลือก 4000 เพราะอะไร** ถ้าจะปรับ ให้ปรับสามค่านั้นพร้อมกันและอย่าให้ตัวไหนแซง 5s

### 18.6 สิ่งที่แก้เพิ่มเมื่อ 2026-08-03 และบทเรียนสองข้อที่เทสต์ปกติจับไม่ได้

**แก้ไปแล้ว**

- **`index.html` มี `<h1>` เดียวแล้ว** — `.fms__h1` ใน mock เปลี่ยนจาก `<h1>` เป็น `<div>`

  ไม่มี selector ไหนพึ่งชื่อ tag** · `<h1>` จริงของหน้าคือชื่อเจ้าของใน `.cover`
- 🔴 **`.grow__note` ต้องอยู่*นอก* `.fms` เสมอ — ห้ามย้ายเข้าไปข้างใน**
  `.fms` ทั้งก้อนมี `aria-hidden="true"` (การอ่านออกเสียง UI ปลอมไม่ช่วยใคร)
  · ถ้า `.grow__note` — บรรทัดที่บอกว่า "ไม่ใช่ภาพหน้าจอ" — ถูกย้ายเข้าไป
  **มันจะหายจาก accessibility tree** = กลายเป็นการอ้างเกินจริงกับคนที่ใช้ screen reader
  ซึ่งผิดกติกาข้อ 9 ของ `CLAUDE.md`
- **เลข eyebrow เรียงใหม่ 01–08 ตามลำดับ DOM ทั้ง EN และ TH** — เดิมซ้ำเลข 02 กับ 03
  และวิ่งถึงแค่ 06
- **`index.html` มี `rel="canonical"` + `og:site_name` แล้ว** ครบทั้ง 5 หน้า
- **`.anno__t` ย้าย `opacity: 0` มาอยู่ใต้ `.js-anim`** — เดิมเป็น `opacity: 0` ลอย ๆ
  ซึ่งผิดกติกาข้อ 3 ของ `CLAUDE.md` เต็ม ๆ

**บทเรียนที่ 1 · specificity เท่ากัน = source order ตัดสิน · กฎ `@container` ก็ไม่มีข้อยกเว้น**

`.js-anim .anno__t` กับกฎใน `@container` ที่เปิดป้ายนั้น **มี specificity เท่ากัน (2 class)**
· ที่กฎ container ยังชนะได้คือเพราะมันอยู่**ท้ายกว่าในไฟล์** ไม่ใช่เพราะมันเป็น container query
· **ถ้าใครย้ายบล็อก `.js-anim .anno__t` ลงมาไว้ใต้ `@container` ป้ายจะไม่โผล่อีกเลย
โดยไม่มี error ที่ไหน** — เป็นกับดักตระกูลเดียวกับ `.wipe.vt-open` ใน §18.3
**เวลาแก้ start state ที่ทับกฎอื่น ให้ดูตำแหน่งในไฟล์ก่อน อย่าดูแค่ selector**

**บทเรียนที่ 2 · บั๊กที่ต้องเข้าสองเงื่อนไขพร้อมกัน คือของที่เทสต์ปกติไม่มีทางจับ**

`@media (prefers-reduced-motion: reduce)` ตั้ง `.grow__card { --g: 1 }` ด้วย CSS ล้วน
· ลำพังอย่างเดียวถูกต้อง · แต่คนที่เปิด reduced motion **และ** JS ตายพร้อมกัน
จะเห็นป้าย `.anno` ของทุก breakpoint **ซ้อนกันที่มุมเดียว** — วัดได้ **3 ใบซ้อนที่ 900px
และ 2 ใบที่ 1100px** · แก้ด้วย `html:not(.js-anim) .anno { display: none }`

**สิ่งที่ต้องจำคือวิธีหามัน ไม่ใช่ตัวบั๊ก** — เกตของโปรเจกต์นี้เทสต์ "ไม่มี JS" อย่างหนึ่ง
และ "reduced motion" อีกอย่างหนึ่ง แยกกัน · **ช่องโหว่อยู่ตรงที่ไม่มีใครเทสต์สองอย่างพร้อมกัน**
· เวลาเพิ่ม fallback ใหม่ ให้ถามเสมอว่า *"ถ้าเงื่อนไขนี้เกิดพร้อมกับ fallback อีกตัวที่มีอยู่แล้ว
จะเป็นยังไง"* โดยเฉพาะเมื่อ fallback ตัวหนึ่งเป็น CSS ล้วนและอีกตัวพึ่ง `.js-anim`

### 18.7 เกตที่ต้องผ่านเพิ่ม เมื่อแตะของในหัวข้อนี้

นอกจากเกตใน §17 ให้เพิ่มหกข้อ:

1. **ทดสอบว่าไม่มี `curtain.js`** (เปลี่ยน `src` ให้ผิดชั่วคราว) แล้วจอแรกต้องยังมาถึงใน 4 วิ
2. **ทดสอบว่าไม่มี `rail.js`** แล้วราง Work ต้องยังปัดถึงทั้งสี่แผงได้
3. **ทดสอบช่วง 860–1000px** ซึ่งเป็นรอยต่อสองอัน: `.panel` เปลี่ยนเป็นคอลัมน์เดียวที่ 860px
   ส่วน pin เริ่มทำงานที่ 1000px — ระหว่างสองค่านี้เป็นแถบที่ไม่มีใครออกแบบมาโดยตรง
4. **ทดสอบ morph จริงจากทั้งสี่แผง** — ต้องบินไปลงที่ hero ของหน้าปลายทาง ไม่ใช่กล่องเปล่า
   และ MeguBot ต้องไม่ถูก crop
5. **ทดสอบ "ไม่มี JS" *พร้อมกับ* "reduced motion"** ไม่ใช่แยกกัน — ดูบทเรียนที่ 2 ใน §18.6
6. **สลับเป็นไทยแล้วไล่อ่านทั้งหน้าด้วยตา** ว่ามีคำอังกฤษค้างไหม
   · `__i18nCheck()` ผ่านไม่ได้แปลว่าแปลครบ (ดูกล่องเตือนท้าย §17)
   · **ต้องเลื่อนรางให้ครบทั้งสี่แผง** ไม่ใช่ดูแค่แผงแรก
   · 🔴 **เกตนี้ต้องรันตอนพาเนล preview แสดงผลอยู่จริง** — ถ้า `document.visibilityState`
   เป็น `hidden` เบราว์เซอร์จะไม่ยิง `requestAnimationFrame` เลย และ `scrollTop` ที่เขียนลงไป
   จะค้างที่ 0 · ผลคือ**ทุกอย่างที่ขับด้วย scroll ดูเหมือนตายทั้งที่ปกติดี**
   (ราง · count-up · `--p`/`--cp`) · ผูกกับกับดักข้อ 2 ท้าย §17 ที่มีอยู่แล้ว
   · ถ้าเลี่ยงไม่ได้ ให้เปลี่ยนไปพิสูจน์*เงื่อนไข*แทนผลลัพธ์ เช่นยืนยันว่า `.rail__count b`
   ยังเป็น node เดิมและยังอยู่ใน document หลังสลับภาษา แทนที่จะรอดูตัวเลขเดิน
   — แต่ต้องเขียนให้ชัดว่าพิสูจน์อะไรไปแล้วและอะไรยังไม่ได้พิสูจน์
