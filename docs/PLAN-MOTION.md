## 2 · ข้อที่ไฟล์นี้ตั้งใจต่างจากเว็บจริง (อย่า "แก้" สิ่งเหล่านี้)

- ไม่มีปุ่มสลับภาษาไทย · ไม่มี nav.js / morph.js / reveal.js — ไฟล์นี้ standalone
- ไม่มีองก์มืด — สนามเดียวทั้งหน้า
- gating ใช้ inline script ใน `<head>` (`js-anim`) + `--lead` แบบของตัวเอง

## 3 · สถาปัตยกรรมที่มีอยู่ (ห้ามรื้อ ต่อยอดเท่านั้น)

- **loader** (revision 4 — สามเวอร์ชันก่อนถูก reject ดู §0): สร้างโดย JS ทั้งหมดเป็น **SVG**
  (ไม่มี JS = ไม่มี overlay) · จิ๊กซอว์**รูปทรงจริง** 13×7 desktop / 7×11 mobile
  (คี่ทั้งสองแกนเพื่อให้มีชิ้นกลางจริง) · ขอบด้านในทุกเส้นมีเดือย neck-and-head
  polarity คำนวณจาก `pol(a,b)` แบบ deterministic และ**สองชิ้นที่ชนกันวาดเส้นโค้งสัมบูรณ์เดียวกัน**
  (ชิ้นหนึ่งเดินหน้า อีกชิ้นถอยหลัง) จึงต่อกันสนิทไม่มีช่องว่าง
  · **สองเฟส**: `loader--cut` วาดเส้นตัดสีมิ้นต์ด้วย `stroke-dashoffset` ไล่จากกลาง (60ms/วง)
    = ตัว loading animation · แล้ว `loader--lift` ชิ้นจางหายทีละชิ้น (110ms/วง + jitter 0/40/80ms)
    **ไม่หมุน ไม่เอียง ไม่บิน** — แค่หายไป
  · **overlay ไม่มี background** — ชิ้นจิ๊กซอว์เองคือสิ่งที่บังหน้าเว็บ พอชิ้นไหนหาย
    หน้าจริงโผล่ตรงรูนั้นทันที (เจ้าของสั่งเอง: "หลุดเเล้วเปิดหน้าจริงเเค่ส่วนที่หลุด")
    · แต่ละชิ้นมีสองพาธ: `.pc__f` navy fill + navy stroke 1.5px (ปิด hairline seam จาก
      antialiasing) และ `.pc__l` เส้นตัดมิ้นต์ · fade ทั้ง `<g>` พร้อมกัน
  · MIN hold 1200ms รอ `document.fonts.ready` + `img.decode()` ของ portrait, cap 2000ms
  · ทุก input → `.is-skip` + `loader--gone` ทันที
  · failsafe สองชั้น: CSS keyframe ซ่อน overlay ที่ 5s · entry เล่นเองที่ `--lead` 3.6s
  · ปุ่มหมุนเวลา: `RING_MS` (135) `CUT_MS` (80) `HOLD` (1500) `FADE` (1000) เท่านั้น
  · **สัดส่วนเดือยคุมว่ามันดู "ผู้ใหญ่" หรือ "ของเล่น"** — `HEAD` (.155) `NECK` (.055)
    `FLARE` (.155) · เจ้าของเคยบอกว่า "ดูเด็ก ดูตลกเเบบเเปลกๆ" ตอน `HEAD` = .30
    (ปุ่มนูน 30px บนช่อง 100px) · ลดเหลือ 16px แล้วรูปทรงกลายเป็นรอยตัดที่บังเอิญ
    ประกบกันได้ ไม่ใช่ตัวต่อเด็ก · **ถ้าจะขยับตัวเลขพวกนี้ต้องรัน coverage test ใหม่**
  · เส้นตัดเป็น cream `#EBEEE7` opacity **.13** ไม่ใช่มิ้นต์ .42 — มิ้นต์สว่างบนพื้นน้ำเงิน
    อ่านเป็น**กระดานเกม** · รอยตัดจริงบนผิวมืดแค่รับแสงนิดเดียว

  · **เส้นตัดต้องหายก่อนชิ้นเริ่มขยับ** (`.loader--lift .pc__l { opacity: 0 }` + ชิ้นดีเลย์ 320ms)
    เจ้าของรายงาน "หลุดเเล้วโชว์กรอบแปลกๆ" — สองสาเหตุพร้อมกัน:
    (ก) ชิ้นหายแล้วแต่**เพื่อนบ้านยังวาดเส้นตามขอบร่วม** = ทุกรูมีขอบครีมล้อม
    (ข) ชิ้นที่ยกตัว `scale` พาเส้นของตัวเอง**หลุดจากรอยต่อ** = เห็นเส้นขนานสองเส้น
    · รูปทรงจิ๊กซอว์ยังอ่านออกจาก**เงาของรู**เอง ไม่ต้องพึ่งเส้น
  · `scale` ตอนยก = **1.035** ไม่ใช่ 1.05 — ชิ้นที่ขยายจะล้ำเข้าไปในรูที่เปิดแล้ว
    เกิดฝ้าน้ำเงินโปร่งบนหน้าเว็บ · ทุก % ที่เพิ่มคือแถบฝ้าที่กว้างขึ้น

  **เคยพิจารณาแล้วไม่เอา: จิ๊กซอว์แบบ scroll-driven** (เลื่อนแล้วชิ้นถึงหลุด)
  เพราะเป็น scroll hijacking บนจอแรก — การหมุนล้อครั้งแรกไปแกะจิ๊กซอว์แทนเลื่อนหน้า
  บนแทร็คแพด/มือถืออ่านว่าเว็บค้าง · และคนที่ไม่เลื่อนจะไม่เห็นอะไรเลย
  ขัดกับกติกาข้อ 1 ของเจ้าของเอง (เห็นชื่อทันที)
### 3.1 · ตัวอักษรที่แตกเป็นชิ้น (`.name` / `.shot__t` / `.end .giant`)
ทุกตัวอักษรเป็น `inline-block` แยกกัน → **line breaker ตัดบรรทัดระหว่างตัวอักษรได้**
เคยได้ "TEERAPA / B / BOONSRI" มาแล้วจริง · กันด้วยสองอย่าง ห้ามถอด:
- `white-space: nowrap` บน `.w` ทุกตัว (กันตัดกลางคำ)
- `.name .w { display: block }` (บังคับสองบรรทัดทุกความกว้าง — ปล่อยให้ wrap เองแล้วได้
  3 บรรทัดที่ 1381px และ 1 บรรทัดที่ 900px)
- `.entry .giant` มี font-size ของตัวเอง เพราะ entry เป็น grid สองคอลัมน์
  ขนาด 11vw ของ `.giant` ล้นครึ่งซ้าย · **เพิ่ม column ใหม่ใน entry เมื่อไหร่ต้องวัดใหม่**

- **หนึ่ง scroll listener + หนึ่ง rAF** ทำ: `--prog` (แถบบน) · `--ep` (entry ถอยเวที)
  · `--sp` ต่อ shot (เลข ghost + parallax ในกรอบ) · word-scrub ของ manifesto
- **IO สองตัว**: one-shot assembly (`.is-in`) + counter นับขึ้น
- ตัวเลขจริงอยู่ใน markup เสมอ — JS เป็นคนถอยไป 0 แล้วนับขึ้น (บั๊ก "0 ค้าง" เคยเกิดและแก้แล้ว)

### P2 · trionn-style hover: ตัวหนังสือ roll-up บนลิงก์/ปุ่ม
ทุก `.shot__go`, `.btn`, `.foot a`: ห่อ label สองชั้น
```html
<a class="roll" href="…"><span class="roll__box"><span>Full case study</span><span aria-hidden="true">Full case study</span></span></a>
```
`.roll__box{display:inline-grid} span{grid-area:1/1; transition:translate .45s var(--ease-out), opacity .3s}`
ชั้นแรก `translate: 0 -110%` ตอน hover, ชั้นสอง เริ่ม `0 110%` → `0 0`
- ทำเป็น **CSS ล้วน** ห้ามใช้ JS · ห้ามขยับตามตำแหน่งเมาส์ (กติกา magnetic)
- reduced motion: ไม่ roll แค่เปลี่ยนสี

### P3 · hover บนกรอบภาพ shot
ตอนนี้กรอบภาพ hover แล้วไม่ตอบอะไรเลย (จืด)
- `a.shot__media:hover img { scale: 1.04 }` transition 1.2s `--ease-out`
  — **ระวัง**: img มี `translate` จาก `--sp` อยู่แล้ว ใช้ `scale` แยก property จึงไม่ชน
- มุมขวาล่างของกรอบ: chip `View case →` (พื้น `--ink` ตัวหนังสือ `#EBEEE7` = 11.27)
  โผล่ด้วย `translate/opacity` ตอน hover/focus-visible · ตำแหน่ง**คงที่** ไม่ตามเมาส์
- มือถือ (pointer: coarse): chip แสดงตลอด ไม่มี hover ให้รอ

### P4 · เลข ghost 01–04 จางเกินไป (จืดเพราะมองแทบไม่เห็น)
- stroke จาก `rgba(13,43,62,.13)` → `.18` และ fallback ทึบจาก `.06` → `.08`
- เพิ่ม drift แนวนอนช้า ๆ : `translate: calc(var(--sp) * -3vw) calc(-50% + var(--sp) * -6vh)`
  (แกน X ใหม่ แกน Y ของเดิม) — เลขจะลอยสวนทางกับ scroll เหมือน parallax อีกชั้น
- **วัด contrast ไม่ต้อง** (เป็น decoration, aria-hidden) แต่ต้องเช็กว่าไม่ทำ body ล้นแนวนอน
  ที่ 360px — เลขอยู่ใน `.shot { overflow: clip }` อยู่แล้ว ยืนยันด้วยเกตความกว้างตามเดิม

  ถ้าเจ้าของบอกช้าไป ปุ่มหมุนอยู่ที่ `RING_MS = 120` กับ `MIN = 680` เท่านั้น อย่าแตะอย่างอื่น

## 5 · เกตที่ต้องรันหลังจบทุกข้อ (ไม่ผ่าน = ยังไม่จบข้อนั้น)

1. **7 ความกว้าง × JS ปิดจริง**: iframe `sandbox="allow-same-origin"` (ห้ามมี allow-scripts)
   ที่ 1440/1280/1024/900/768/390/360 — เนื้อหาเห็นครบ, `scrollLeft` ดันไม่ไป (=0),
   portrait โผล่, counter โชว์เลขจริงไม่ใช่ 0
2. **contrast**: คู่สีใหม่ทุกคู่วัดจริงด้วยสูตร WCAG ก่อนเชื่อ — ตัวเล็ก ≥4.5 ตัวใหญ่ ≥3
   สีมี alpha ต้องผสมทับพื้นก่อนวัด
3. **reduced motion**: ทุก effect ใหม่ต้องมี override ในบล็อก `prefers-reduced-motion` เดียว
   ท้ายไฟล์ — หน้าต้องอ่านจบได้แบบนิ่งสนิท
4. **console สะอาด** และ **ไม่มี rAF loop ถาวร** — scroll เงียบ = ศูนย์งานต่อเฟรม
5. **ความจริงของเนื้อหา**: ห้ามพิมพ์ตัวเลข/ประโยคใหม่เอง — ทุกคำลอกจาก `index.html`
   หรือมีที่มาใน `docs/CONTENT-SOURCE.md` · โดยเฉพาะ MeguBot ต้องคงประโยค
   "I designed the system and the features; my friend wrote the code."

**กับดักการทดสอบ (เคยเสียเวลาจริงทั้งคู่ — HANDOFF §17 มีรายละเอียด):**
- iframe ที่จอดนอกจอ (`left:-99999px`) IntersectionObserver ไม่ยิง — จอดในจอที่ `opacity:.01` แทน
- preview pane ที่ไม่ composite: ไม่มีเฟรม ไม่มี rAF, CSS transition ไม่เดิน, screenshot ค้าง
  — วัด computed value / ปิด transition แล้ววัด end state แทน อย่ารอดูด้วยตา

**กับดักที่เจอจริงตอนทำ P1–P7 — อย่าพลาดซ้ำ:**
1. **specificity ของ hover ชนกับ `.is-in`** — `.js-anim .shot.is-in .shot__media img` = (0,4,1)
   ทับ `.shot__media:hover img` = (0,2,1) · hover จะ**ไม่ทำงานเงียบ ๆ** ต้องเขียน hover ที่ระดับลึกเท่ากัน
   · เกิดกับทั้ง P3 (ภาพ) และ P7 (`.role`) · ทุกครั้งที่เพิ่ม hover บน element ที่มี `.is-in` ต้องเช็ก
2. **แก้ selector แล้วลืม declaration** — ตอนแก้ specificity ของ P3 ผมลบบรรทัด
   `transition: scale ...` ทิ้งโดยไม่ตั้งใจ · hover เลยกระตุกทันที ไม่มี transition
   · เช็กด้วยการอ่าน `getComputedStyle(...).transition` จริง
3. **ticker 2 ชุดมีช่องว่าง** — หนึ่งชุดกว้าง 969px แต่ container 1280px
   พอ `-50%` หางแถวพ้นขอบขวา = เห็นช่องว่าง · **กฎคือครึ่งแถวต้องกว้าง ≥ container**
   → 4 ชุด (ครึ่ง = 1938px) · วัดทุกครั้งที่เปลี่ยนขนาดฟอนต์หรือข้อความ
4. **`getComputedStyle(el)` ไม่รับ pseudo** — เทสต์รอบแรกอ่าน `::after` ไม่เจอเพราะ helper
   ผมรับ arg เดียว · ต้อง `getComputedStyle(el, '::after')`
5. **`::before` ใส่ `aria-hidden` ไม่ได้** — เลข index ของ role ตอนแรกใช้ alpha .3
   วัดได้ **1.8:1** = จางจนอ่านไม่ออกและไม่ใช่ decoration ที่ซ่อนได้ · เปลี่ยนเป็น `--dim` (5.29:1)
